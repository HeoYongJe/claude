## 1. Overview
- 브랜드명: travel
- 한 문장: 전날 종가 환율(매일 갱신되는 데이터) + 현지 물가지수(빅맥·코카콜라·생수)로 "지금 원화로 가장 이득인 여행지"를 추천
  (2026-10-18: "전날 환율"은 **데이터 신선도**를 뜻함 — 오늘 쓰는 환율값 자체가 전날 종가. **순위를 가르는 비교 기준**(§11)은 별개 개념이니 혼동하지 않게 구분.
  2026-10-19: 비교 기준을 **"한 달 전 대비" → "일주일 전 대비"로 변경**. 자세한 이유·근거는 §11 참고.)
- 무드: **네오 브루탈리즘(2026-10-20 전면 리뉴얼, 같은 날 2차 수정)** — 쿨그레이 페이지 배경 위에 화이트 카드를
  하드 섀도우로 띄우고, 솔리드 블랙 매스(GNB·핵심 요약 박스)로 무게감을 주는 구조. 애시드 옐로우는 블랙 배경 위
  뱃지·CTA 텍스트로만 제한. "이미지보다 타이포그래피·데이터 수치 자체가 디자인"이 원칙. 구 "하늘/구름 영상 +
  글래스모피즘" 배경 영상, 블롭 글로우, 우측 항로 레일(비행기 애니메이션), 스크롤 배경 블루시프트는 전부 제거됨.
  **2차 수정(같은 날) 배경**: 1차 결과물이 사용자가 참고로 보여준 다른 사이트(job.jobzorro.kr — 역시 화이트+블랙+
  옐로우 하이라이트+2단 히어로 구성)와 지나치게 비슷해 보인다는 지적과, "텍스트 형광펜 하이라이트·중앙정렬·
  얇은 선 분할"을 금지하는 구체적 브리프를 받아 수정. 바뀐 점: ①제목 텍스트의 옐로우 배경 하이라이트 전면 금지(뱃지/
  CTA 텍스트로만 제한, 강조는 밑줄로) ②페이지 배경을 순백 대신 쿨그레이(`#F1F5F9`)로 바꿔 화이트 카드와 면대비를
  만듦 ③GNB와 랭킹 섹션의 핵심 요약 박스(`.t-summary`)를 완전한 솔리드 블랙으로 ④하드 섀도우를 다시 키움(전 토큰
  +2px, `--shadow` 6px)인데, **다만 "모든 요소에 상시 섀도우"였던 10/20 1차 톤다운 지적은 여전히 유효** —
  이번에 섀도우가 돌아간 곳은 카드 "컨테이너" 레벨뿐(뱃지·pill·작은 뱃지류는 여전히 플랫). 상세는 §2·§5·§6·§7·§8.
  (관성 스크롤(lerp)·카드 등장 애니메이션 등 모션 자체는 유지.)
- 구성(원페이지): 히어로 → **서비스 소개("왜 필요?")** → 실시간 추천 랭킹(나라 클릭 시 상세뷰로 슬라이드 전환) → 푸터
  (2026-08-02: why 섹션을 히어로 바로 다음·랭킹 앞으로 이동 — "나라 하나 본 뒤 서비스 설명" 흐름 어색함 해소.
  구 "체감 물가"·"여정"·CTA 섹션은 제거됨.)

## 2. Colors
`css/style.css`의 `:root` 토큰이 단일 소스.

> **2026-10-20, 네오 브루탈리즘으로 전면 교체.** 아래가 현재 색 시스템이며, 이전 Primary 블루(`#0E4AEB`) 기반
> 체계는 완전히 폐기됐다(과거 기록은 git 태그 `gappun-261020-backup`, "261020백업" 백업 참고).
> 핵심 변경: ① 배경 이미지·그라디언트·투명도(글래스모피즘) 전면 제거, 배경은 순백 고정.
> ② 구조·텍스트·보더·CTA 배경은 전부 솔리드 블랙 하나로 통일(구 Primary 블루 역할을 흡수).
> ③ 애시드 옐로우는 **블랙 배경 위의 텍스트/포인트로만** 사용(흰 배경에 옐로우 글자 금지 — 명도 대비 깨짐).
> ④ "오름/내림" 방향색은 블루 단일 역할에서 **핑크레드(오름·비쌈)/블루(내림·쌈)** 2색 체계로 분리.

| 역할 | 토큰 | 값 | 사용처 |
|---|---|---|---|
| Page Background | `--bg` | `#F1F5F9` (옅은 쿨그레이) | **2026-10-20 2차: 순백 → 쿨그레이로 변경** — 화이트 카드가 보더+섀도우뿐 아니라 면 색 차이로도 분리되게 함 |
| Structure & Text | `--ink` | `#111111` | 기본 텍스트, 카드·버튼 테두리, GNB·CTA·강조 카드 배경 |
| Brand Point | `--accent` | `#DFFF00` (애시드 옐로우) | **블랙 배경 위 뱃지·CTA 텍스트로만** — 텍스트 배경 하이라이트 금지(2026-10-20 2차) |
| Data Up(강세·비쌈) | `--up` / `--up-tint` | `#FF2A5F` / `#FFE4EC` | 환율 ▲, 체감물가 비쌈, 품목가 오름 |
| Data Down(약세·쌈) | `--down` / `--down-tint` | `#005AEB` / `#E2EBFC` | 환율 ▼, 체감물가 쌈, 품목가 내림 |
| Muted(보조 텍스트) | `--muted` / `--muted2` | `#5A5A5A` / `#8A8A8A` | 라벨·메타 텍스트(5색 브랜드 팔레트 밖의 중립 톤) |
| Surface(중립 면) | `--surface` | `#E7ECF3` | 탭 트랙 등 장식 아닌 중립 배경(페이지 배경보다 한 톤 더 진함) |
| Hard shadow | `--shadow` 등 | `4/6/8px Npx 0px var(--ink)` | 블러 없는 벤토 박스 그림자(§5, 2026-10-20 2차에 6px로 재상향) |

- **텍스트 하이라이트 금지(2026-10-20 2차, 엄격 규칙):** 제목·본문 텍스트에 배경색을 칠하는 "형광펜" 효과는
  어디에도 쓰지 않는다(히어로 타이틀 `em`도 포함 — 구현은 `box-shadow: inset 0 -10px 0 -2px var(--accent)`로
  만든 두꺼운 밑줄 하나로 대체). 옐로우는 오직 ①작은 뱃지(eyebrow pill, 환율 badge) ②아이콘 배경
  ③블랙 배경 카드/버튼 안의 텍스트, 이 세 용도로만 쓴다.

- **색 규칙 — 방향 기준 유지, 색상값만 교체(2026-08-02 규칙 승계):**
  - **모든 증감 수치는 "좋다/나쁘다"가 아니라 방향(오름/내림)으로 색을 정한다.**
    **오름(+,▲)=`#FF2A5F` / 내림(−,▼)=`#005AEB`.** 예외 없이 전 지표 동일(환율·체감물가·품목가·도시지수 전부).
  - **"유리/이득" 의미는 색이 아니라 텍스트 라벨로만** 표현.
  - 구현: `main.js`의 `dirColor(isUp)`/`dirTint(isUp)`(`DIR_UP/DIR_DOWN` 상수만 새 값으로 교체, 호출부는 그대로) —
    랭킹 뱃지·스파크·체감물가 pill·품목%·도시지수·히어로 뱃지·상세 대표숫자 전부 동일 함수 사용.
  - **예외: 블랙 절약 카드 안 텍스트는 옐로우/흰색 유지**(카드 자체가 블랙 면) — 방향은 ±·▲▼ 기호로만 표현.
  - **카드 인사이트(`.rc-insight`) 3상태도 방향색에 합류**: 비쌈=Up(핑크레드) / 동일=중립(Muted) / 쌈=Down(블루).
    구 앰버 경고색은 폐기(5색 팔레트 안에서 "비쌈"을 "오름" 방향으로 재해석해 통일).
  - **데이터 타이포그래피**: 환율·금액 등 핵심 숫자는 Ink `#111111` 굵은 폰트(Pretendard 800)로 크게. 숫자 옆
    증감 지표(▲/▼ %)만 Up/Down 컬러로 — 숫자 본체에는 방향색을 넣지 않는다(브리프 원칙).

## 5. Radius & Elevation
- **Radius:** 카드 14–16px · 큰 카드/패널 18px · 버튼 10–12px · pill 999px
  (2026-10-20: 블러 섀도우 시대의 20/24px보다 살짝 줄임 — 하드 섀도우와 결합할 때 너무 둥글면 벤토 박스 느낌이 약해짐.)
- **Shadow(2026-10-20 도입 → 같은 날 톤 다운):** 블러 0, 전부 `Npx Npx 0px var(--ink)`.
  **1차 구현(전부 상시 그림자)은 사용자가 바로 지적**: 카드·버튼·뱃지 등 거의 모든 요소에 하드 섀도우를 깔았더니
  흔한 "네오 브루탈리즘 템플릿" 느낌이 나고(참고로 든 레퍼런스 사이트와 구도가 비슷해 보임), 과했음.
  → **2차: 그림자는 "진짜로 떠 있어야 하는" 소수의 요소에만**(CTA 버튼·히어로 카드·모달만), 나머지는 보더만 있는
  평면 + hover 시에만 그림자. 토큰도 1px씩 하향(`--shadow` 4→3px).
  → **3차(현재, 같은 날 2차 수정 브리프):** 사용자가 이번엔 반대로 **"흐릿한 드롭 섀도우 대신 블러 0의 두껍고
  날카로운 그림자(`6px 6px 0 #111`)를 강하게" 명시** — 2차의 "섀도우 과다" 지적과 모순돼 보이지만, 핵심은
  **"모든 요소에 무차별 적용"이 문제였지 섀도우 자체가 문제가 아니었다**는 것. 3차는 섀도우를 다시 키우되
  ①카드 "컨테이너" 레벨에만 적용(뱃지·pill·작은 아이콘 박스는 여전히 플랫 — 중첩 섀도우 금지)
  ②페이지 배경을 쿨그레이로 바꿔 카드가 보더+섀도우뿐 아니라 **면 색 차이로도** 분리되게 함(§2)
  ③GNB·요약 박스를 완전 블랙 매스로 바꿔 획일적인 "흰카드+그림자 반복" 패턴을 깨뜨림(§6·§7)
  — 이 세 가지를 함께 써서 "매 요소가 똑같이 그림자 진 템플릿"이 아니라 의도적으로 설계된 화면처럼 보이게 함.
  **지금 상시 그림자가 있는 카드**: `.t-rcard` `.t-summary`(블랙) `.why-card` `.price-card` `.dcard` `.save-card`(블랙)
  `.d-savecard`(블랙) `.t-pop-tile__btn` `.t-pop__all` `.t-fxcard`(블랙) `.t-modal__panel`.
  토큰: `--shadow-sm`(4px)·`--shadow`(6px, 브리프 지정값)·`--shadow-lg`(8px).
- **Hover/Active(2026-10-20):** 상시 그림자가 있는 카드는 hover 시 `translate(-3px,-3px)` + 그림자가 더 커지며
  (예: 6px→9px) "떠오르는" 느낌, active(클릭) 시 `translate(2~6px)` + 그림자를 줄여 "눌리는" 느낌(그림자가 눌림의
  물리적 단서가 됨 — 브루탈리즘 핵심 상호작용). 블랙 배경 위 CTA(GNB·요약 박스 안)는 그림자가 안 보이므로
  hover 시 그림자 대신 `opacity:.82`만 적용. 카드 hover/active 효과는 전부 CSS로만(JS 인라인 스타일 제거).
- **보더:** 모든 카드·버튼 테두리는 `1px solid var(--ink)`(블랙) — 구 라이트그레이 보더(`#EEF1F6` 등)는 폐기.
  라이트그레이 선으로 영역을 나누지 않는다. 박스 좌측 컬러 스트라이프 금지.

## 6. Fixed Elements (고정 요소)
1. **상단 진행 바** — `fixed; top:0; height:4px`, 블랙 바가 스크롤 진행률 0→100%(`transform:scaleX`, 색만 Primary→Ink 교체).
2. **네비(GNB)** — `fixed; top:0`. **2026-10-20 2차: 완전한 솔리드 블랙(`var(--ink)`)**(1차의 "흰 배경+1px 블랙
   보더"는 폐기 — 브리프의 "GNB 전체 배경을 블랙으로 덮어 화면 위아래 무게감" 지시 반영. 화면 최상단에 강한
   블랙 매스를 둬 얇은 선 하나로만 섹션을 가르던 인상에서 벗어남). 브랜드 텍스트는 흰색으로 반전.
   **요소 2개만**(좌우 양끝): 좌 브랜드 "가뿐"(흰 텍스트, 클릭 시 맨 위로 스크롤, `.t-nav-brand`) / 우 "추천 랭킹" 버튼.
   **GNB 안의 CTA는 블랙 배경 위라 기본 블랙+옐로우텍스트 버튼이 묻히므로 색을 반전**(`.nav .t-cta` — 옐로우 배경
   + 블랙 텍스트 + 그림자 없음, 블랙 바탕에 블랙 그림자는 안 보이므로). hover는 그림자 대신 `opacity:.82`.

  **변동률(changePct)의 비교 기준은 "일주일 전 대비"**(`seriesMetrics`, `weekAgoTargetMs = currentDate - 7일`) — 화면 문구는 전부 "최근 일주일" 등으로 명시(히어로 eyebrow·랭킹 타이틀·상세 fx 라벨·팝업 정렬 note).
  ⚠️ **비교 기준 변천사**: 최초 구현(2026-07-20)부터 2026-10-18까지는 **한 달 전 대비**였음(디자인 핸드오프 문서엔 원래 "전일 대비"로 적혀 있었으나, 하루 변동폭(±0.1~0.5%)은 변별력이 없어 처음부터 한 달 기준으로 구현). **2026-10-19, 한 달 → 일주일로 재변경.** 사유:
  - 한 달 기준은 Top3 구성이 며칠~1주 단위로만 바뀌어 "사이트가 정적이다"는 지적(사용자 피드백) — 매일 들어와도 똑같아 재방문 동기가 약함.
  - 하루 기준은 반대로 너무 자주/무질서하게 바뀜 — 실측해보니 같은 통화(JPY)가 이틀 만에 −0.99%→+1.05%로 부호가 뒤집히는 등 **추세가 아니라 노이즈**라 신뢰도가 낮음(2026-10-19 확인, 10/14→15와 10/15→16의 변동 방향이 통화 대부분에서 정반대였음).
  - **일주일 기준을 실측 검증**: 10/9~10/16 매일 "7일 전 대비 Top3"를 계산해보니 거의 매일 구성이 바뀌면서도(예: 10/9 스위스·인도·일본 → 10/12 멕시코·튀르키예·폴란드 → 10/16 브라질·이스라엘·멕시코) 하루 기준처럼 부호가 뒤집히는 극단적 노이즈는 없어 "매일 바뀌는 느낌 + 추세로서의 신뢰성"을 동시에 만족 → 일주일로 확정.
  - 트레이드오프: 한 달 기준 대비 변동 폭 숫자가 작아짐(한달 ±2~9% → 일주일 ±0.5~2.6%대). 문구에 "일주일" 기간을 명시해 작은 숫자 자체가 문제되지 않도록 함.
  - 코드: `lib/ranking.js`의 `seriesMetrics`·`buildRanking` 두 곳의 `30 * 86400000` → `7 * 86400000`(변수명도 `monthAgo*` → `weekAgo*`). 과거 시점 수집 범위(12주, 3개월 최저 계산용)는 변경 없음.
  - ⚠️ **배포 제약**: 이 계산은 서버(`lib/ranking.js`)에서만 하고 클라이언트는 그 결과를 그대로 쓰기 때문에(월→일주일 전환은 지난번 "환율만 랭킹" 변경과 달리 **클라이언트가 멱등하게 재보정할 수 없음** — changePct 값 자체가 서버 계산 결과라서), **Vercel을 재배포해야만 라이브 숫자가 실제로 일주일 기준으로 바뀐다.** 이 세션에선 Vercel이 로그아웃 상태라(`vercel login` 필요, 대화형 OAuth라 에이전트가 대신 못 함) 코드·문구만 준비해두고 재배포는 사용자 액션 대기 중.
  **순위 산정(2026-10-18 변경 — 환율 변동만, 물가 제외):** 결합 점수(환율+물가 1:1)를 썼더니 스케일 차이(환율 ±10% vs 물가 -70~+50%)로 사실상 물가가 순위를 단독 결정했고, 물가가 구조적으로 낮은 나라(인도네시아·필리핀·말레이시아)가 상위를 영구 점유 → 순위가 정적이 됨("매일 갱신" 전제 붕괴).
