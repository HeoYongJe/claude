# Design Guide — nike 프로젝트

> 이 문서는 이 프로젝트의 디자인 기준이다.
> 모든 화면과 컴포넌트는 이 문서를 먼저 읽고 따른다. 규칙과 어긋나면 만들기 전에 멈추고 물어본다.

## 1. Overview
- 성격: **포트폴리오용 비주얼 케이스스터디** (실제 서비스 아님, 데이터 없음)
- 컨셉: 나이키 브랜드를 소재로 한 **가상 캠페인/컨셉 랜딩 페이지** — 2021년식 jQuery 클론 사이트(구버전)를
  대체하는 완전히 새 디자인. "나이키라면 이런 캠페인 페이지를 만들었을 것 같다"는 톤.
- 브랜드명·워드마크는 나이키를 그대로 쓰되(이름 새로 짓지 않음), **스우시 로고 이미지 자산은 복제하지 않는다**
  (상표 이미지 그대로 베끼는 건 피하고, 워드마크는 타이포그래피로 직접 구현).
- 제품 비주얼: 지금은 **추상 그래픽(그라데이션·도형)**으로 채움. 실제 신발 사진/목업은 **사용자가 나중에 직접
  구해서 교체**(코드에 플레이스홀더 교체 지점을 명확히 주석으로 남길 것).
- 구성(원페이지): 히어로 → 매니페스토(짧은 선언문) → 제품 쇼케이스(스크롤 인터랙션) → 기능 하이라이트 →
  룩북 갤러리 → CTA(드롭 알림 신청, 실제 전송 없음) → 푸터
  ⚠️ **2026-11-03: 4개의 "액트"로 재구성** — 스크롤 경험을 HERO/MANIFESTO/PRODUCT/LOOKBOOK 네 덩어리로
  인식하도록 콘텐츠를 재배치. **PRODUCT** = 제품 쇼케이스(스테이지 핀)+기능 하이라이트+BY THE NUMBERS
  스펙(기존엔 독립 섹션, 이제 `.showcase`의 형제 블록)이 한 어두운(`--ink`) 블록. **LOOKBOOK** = 룩북
  갤러리+CTA(기존엔 독립 섹션, 이제 `.speedfield` 래퍼 안에 같이 묶임)가 한 블록(흰 배경에서 CTA의
  `--volt` 색 블록으로 마무리).
  ⚠️ **2026-11-03 11차: 액트 경계 원페이지 스냅 전체 제거** — 위 문단의 "액트 경계에만 스냅 적용"은
  더 이상 사실이 아님. 휠을 가로채 픽셀 좌표로 강제 점프시키던 스냅 시스템(tails)이 섹션 길이·뷰포트·
  스크롤 속도 조합마다 새 엣지 케이스를 계속 만들어내 통째로 걷어내고 전 구간 보통 스크롤로 되돌림 —
  근거와 시행착오는 Motion §5, Components "제품 쇼케이스" 9~11차, "커스텀 휠 스무스 스크롤" 12~15차
  참고. 매니페스토는 16차부터 스크롤 스크럽 자체가 없어져 액트 경계 개념과도 무관해짐.
  ⚠️ **2026-11-05 39차: 다시 뒤집힘 — 전체가 네이티브 `scroll-snap` 패널 구조로 재구성됨.** 11차에서
  걷어낸 "JS로 섹션 경계 강제 점프"와는 다른 방식(브라우저 네이티브)으로, 결과적으로 액트보다 더
  잘게(히어로·매니페스토·신발 스테이지·기능 하이라이트·BY THE NUMBERS·룩북·CTA, 7개) 한 화면씩
  전환되는 구조로 돌아옴 — 자세한 배경·구현·버그는 Motion §5 39차 참고.
  ⚠️ **2026-11-06 40차: 배경 웨이브 제거 + PRODUCT 재통합.** 섹션별 완전한 블랙/화이트(아래 §2
  원래 규칙)로 되돌리고, 7개로 쪼갰던 패널 중 신발 스테이지/기능 하이라이트/BY THE NUMBERS를 다시
  **PRODUCT 패널 1개**로 합침(신발 왼쪽, 타이틀+기능 리스트 오른쪽 2단, 그 아래 BY THE NUMBERS
  압축 바) — 결과적으로 히어로·매니페스토·PRODUCT·룩북·CTA **5개** 패널 구조. Motion §5 40차 참고.

## 2. Colors
`css/style.css`의 `:root` 토큰이 단일 소스.

| 역할 | 토큰 | 값 |
|---|---|---|
| Ink(기본 배경, 히어로/CTA) | `--ink` | `#0A0A0A` |
| Ink 2(다음 톤, 카드 등) | `--ink2` | `#171717` |
| Paper(밝은 섹션 배경) | `--paper` | `#FFFFFF` |
| Paper muted(연한 회색 섹션) | `--paper2` | `#F5F5F5` |
| 포인트(액센트, CTA·하이라이트) | `--volt` | `#D7FF3E` |
| 본문(밝은 배경 위) | `--text` | `#111111` |
| 보조 텍스트(밝은 배경) | `--muted` | `#6B6B6B` |
| 본문(어두운 배경 위) | `--text-on-dark` | `#F5F5F5` |
| 보조 텍스트(어두운 배경) | `--muted-on-dark` | `#9A9A9A` |
| 경계선(밝은 배경) | `--border` | `#E6E6E6` |

- **흑백 대비가 기본 언어**: 섹션 단위로 완전한 블랙 또는 완전한 화이트를 쓰고, 중간 회색 배경은 최소화.
- **Volt(네온 옐로우그린)는 CTA·강조 한 곳에만** — 남용 금지(포인트 색이 희석되면 효과 없음).
- 컬러 사진/목업을 나중에 넣을 때도 이 톤(고대비 흑백 + volt 포인트)에서 크게 벗어나지 않게.
- **specs~lookbook 장식 레이어 색 시행착오(2026-10-29)**: 흰 배경이 밋밋하다는 피드백으로 보조 액센트
  도입을 한때 검토·적용했었음 — 1차(블루 단색 스트로크) → 2차(volt+오렌지+크림슨 그라데이션 리본)까지
  갔으나, **"그라데이션 빼고 포인트컬러만으로 블러 처리된 큼직한 덩어리를 배경처럼 배치해달라"는 3차
  피드백으로 보조 액센트(`--accent2`/`--accent3`)를 전부 제거하고 volt 단일 포인트컬러로 되돌림** —
  위 "Volt는 CTA·강조 한 곳에만" 원칙에 대한 예외가 더 이상 필요 없어짐(자세한 시행착오 과정은 Motion
  섹션의 "specs~lookbook 배경 장식 레이어" 항목 참고).

## 3. Typography
- **디스플레이(헤드라인)**: `Oswald`(Google Fonts, condensed bold) — 나이키 특유의 압축된 임팩트 서체 톤을
  웹폰트로 근사. 전부 대문자 + 넓은 letter-spacing 금지(오히려 타이트하게, -0.01~-0.02em).
- **본문**: `Pretendard`(한국어) — 다른 프로젝트와 동일 소스, 로딩 중복 없음.
- H1(히어로) 96px / 800 / line-height 0.95 (모바일 56px)
- H2(섹션 제목) 56px / 700 / line-height 1.0 (모바일 36px)
- 본문 16–18px / Pretendard Regular~600 / line-height 1.6
- 라벨/키커 13px / 700 / letter-spacing .08em / 대문자

## 4. Layout & Spacing
- 8px 그리드. 콘텐츠 최대 너비 1200px, 좌우 여백 24px(모바일 20px).
- 섹션은 **풀블리드(배경은 뷰포트 전체)** + 내부 콘텐츠만 1200px 정렬.
- 섹션 간 경계는 색 대비(흑/백 전환)로 구분 — 카드 테두리·그림자 남용 금지.

## 5. Motion
> **2026-10-19 1차**: "가뿐처럼 절제된 톤"이 아니라 화려하고 인터랙션이 강한 톤으로(사용자 지시). 커스텀 커서·
> 마그네틱 버튼·3D 틸트를 추가했으나 → **사용자 피드백: "살짝 과함, 인터랙션을 다 때려넣은 느낌. 원한 건 디테일보다
> 전체적인 화려함 — 큼직큼직하고 스크롤링에 따른 변화."** 즉 마우스 정밀도에 의존하는 "디테일 레이어"를 여러 개
> 겹치는 게 아니라, **스크롤에 반응해 화면 전체가 크게 움직이는 적은 수의 임팩트 있는 연출**을 원함.
>
> **2026-10-19 2차(현재 방향)**: 커스텀 커서·마그네틱 버튼·3D 틸트 **제거**. 대신 스크롤 스크러빙 기반의
> 큰 전환 효과에 집중.
>
> **2026-10-30 예외 — 룩북 Fluid Hover Accordion**: 새 룩북 패턴을 제안하자 "마우스 정밀도 의존 인터랙션은
> 한 번 걷어낸 적 있다"고 먼저 알리고 확인을 구함 → **사용자가 "데스크톱은 호버, 모바일은 탭으로 펼치게
> 해줘"로 명시적으로 승인** — 1차에서 걷어낸 건 좁은 영역에 여러 겹 디테일 레이어가 쌓인 과잉이었고,
> 이번 건 섹션 하나의 주된 인터랙션(스크롤 대신 호버가 전환 트리거)이라 성격이 다름, 모바일은 탭으로
> 동등하게 동작. 자세한 구현은 아래 Lookbook 항목 참고.
>
> **2026-11-02 — "마우스 정밀도 의존 디테일 레이어" 원칙 자체를 사용자가 재정의**: 쇼케이스 배경에
> 커서 반응형 "Kinetic Grid"(사용자 제공 React/Framer 컴포넌트를 포팅)를 추가하자고 제안하며 위
> 원칙과의 충돌을 먼저 알리고 확인을 구함 → **사용자: "design.md는 나이키에만 국한된 게 아니라
> 포트폴리오 전반 기준이고, 바꿔달라고 하면 그때그때 바꿔주면 된다"** — 즉 이 문서는 고정된 금지
> 규칙이 아니라 그 시점까지의 합의를 기록한 것이고, 새 요청이 오면 그 요청이 최신 기준이 됨을
> 명확히 함. 이후 디자인 결정에서도 과거 history 항목이 현재 요청과 충돌하면, 충돌 사실만 짚어
> 알리고 사용자 판단에 따르면 됨(막는 규칙이 아니라 참고 기록). 구현 상세는 아래 "제품 쇼케이스"
> 항목 참고.

- 스크롤 등장: 아래→위 페이드업(`opacity 0→1, translateY 40→0`), `IntersectionObserver` 1회 트리거(기본 베이스는 유지).
- **스크럽 스무딩(2026-10-19 1차, "효과가 더 부드러웠으면" 피드백):** 히어로 줌아웃·매니페스토 핀드줌·쇼케이스 비주얼
  스크럽 전부, 실제 `scrollY`를 바로 쓰지 않고 **lerp로 보간한 `smoothY`**를 공통으로 사용(가뿐 히어로 패럴럭스의
  lerp(0.09)와 동일 패턴). 계산 기준도 `getBoundingClientRect`(매 프레임 레이아웃 재계산 필요) 대신
  `offsetTop`/`offsetHeight`를 `resize`에 한 번만 캐시해두는 방식으로 바꿔 성능도 더 가벼워짐.
  ⚠️ **2차(같은 날, "섹션 전환·폰트 애니메이션이 딱딱 끊김" 추가 피드백):** lerp(0.085)만으론 부족 — 원인 둘 더 찾음:
  ①`.grain`(필름 질감 오버레이)의 `mix-blend-mode: overlay`가, 그 아래 레이어가 매 프레임 스크럽으로 바뀔 때마다
  블렌드 영역 전체 재합성을 유발해 스크롤 중 프레임이 끊겼음 → blend-mode 제거(opacity만으로 유사 효과 유지).
  ②lerp 계수를 0.085→**0.06**으로 낮춤(더 천천히 따라가게) — 마우스 휠처럼 값이 듬성듬성 들어오는 입력에서도
  개별 틱이 뭉개져 보이도록. ③스크럽 대상 요소(`.hero__inner`, `.manifesto__text`, 쇼케이스 SVG)에
  `backface-visibility: hidden` 추가해 GPU 레이어 합성을 더 안정적으로(폰트 서브픽셀 흔들림 완화 목적).
- **히어로 키네틱 타이포**: "NIKE" 4글자를 개별 `span`으로 쪼개 글자마다 다른 지연으로 scale+rotate+blur-in(유지).
- **히어로 스크롤 줌아웃(유지)**: 스크롤을 시작하면(0~1 viewport height 구간) 히어로 콘텐츠가 `scale` 커지면서
  `opacity` 빠지는 줌 통과 전환. `hero-wrap`(200vh)이 스크롤 공간을 주고 `.hero`는 그 구간만 sticky.
  ⚠️ **2026-10-20 시행착오**: "섹션 전환이 밋밋하다"는 피드백을 "다음 섹션이 이전 섹션 전체를 덮어야 한다"로
  잘못 해석해서, 한때 `.hero`를 바운드 없는 sticky(영구 고정)로 바꾸고 `.manifesto`가 전체를 덮어 올라오게
  만든 적이 있었음 → **"그 인터랙션(줌아웃) 좋았는데 왜 뺐냐, 전체를 덮으라는 게 아니라 배경만 attachment
  느낌을 달라는 거였다"는 피드백으로 되돌림.** 줌아웃은 그대로 복원하고, 실제 요청은 아래 "배경 패럴럭스"로 해결.
- **배경 패럴럭스("background-attachment" 느낌, 2026-10-20):** 섹션 전체가 아니라 **배경 레이어만** 콘텐츠와
  다른 속도로 움직여서 전환에 깊이감을 줌 — 전체를 덮는 과장된 연출이 아니라 은은한 터치.
  - `.manifesto__bg`/`.showcase__bg`: 가뿐 히어로 패럴럭스와 동일한 공식 `translateY(-(요소중심−뷰포트중심)*speed)`를
    `data-speed`(각각 0.15 / 0.2)로 적용. 이 두 섹션은 보통 문서 흐름으로 스크롤되므로(내부에 sticky 핀/비주얼만
    있고 섹션 자체는 sticky 아님) 뷰포트 안에서 위치가 바뀌어 이 공식이 정상 작동함(실측: scrollY 1400에서
    `.manifesto__bg`가 `translateY(-7.6px)`로 변함 — 확인됨).
    ⚠️ **버그(2026-10-20, 사용자가 스크린샷으로 지적):** 처음엔 `.manifesto__bg`에 직접 `inset:-10%`만 주고
    클리핑을 안 했는데(섹션 자체에 `overflow:hidden`을 주면 형제인 `.manifesto__pin`의 sticky가 깨져서
    일부러 뺐었음), 그 결과 **매니페스토가 아직 뷰포트에 들어오기도 전인데 배경(-10% 위로 확장 + 패럴럭스
    오프셋)이 히어로 영역까지 새어나와 겹쳐 보이는 가로 이음새**가 생겼음(실측: `manifestoRect.top=950`로

    스무스했으면, 슬라이드 모양 통일, 가운데 슬라이드 위쪽이 라운드가 아니라 직각으로 잘림, 마우스
    휠로 페이지 스크롤할 때 슬라이드 안 컨텐츠가 반응함" — 네이티브 scroll-snap 방식을 전부 버리고
    인덱스 기반 `translateX` 커스텀 캐러셀로 전면 재작성:**
    - **구조 전환**: `overflow-x:auto` + `scroll-snap-align` 조합을 버리고, `.lookbook__viewport`
      (`overflow-x:hidden`, 스크롤 가능 축 없음) 안의 `.lookbook__track`을 js가 `transform:translateX()`로
      직접 움직이는 방식으로 교체. 매번 `offset = 뷰포트폭/2 - (인덱스*스텝 + 슬라이드폭/2)` 공식으로
      "현재 인덱스 슬라이드가 정확히 뷰포트 중앙"이 되도록 계산 — 첫/마지막 슬라이드도 항상 정확히
      중앙에 와서 빈 공간이 구조적으로 생길 수 없음(2차의 padding 어림짐작 방식의 근본 한계 해소).
    - **버그 1 — 센터링이 실제로는 안 맞던 원인**: 처음 구현 때 오프셋 공식에 "슬라이드 폭의 절반" 대신
      "스텝(슬라이드폭+gap)의 절반"을 써서 매번 gap의 절반(12px)만큼 중심이 어긋나 있었음(사용자가
      스크린샷으로 지적한 "처음·끝이 비어있다"가 바로 이 오차). 추가로 더 큰 오차의 진짜 원인은
      슬라이드 폭을 `getBoundingClientRect().width`로 측정한 것 — 이 값은 CSS `transform: scale()`이
      이미 적용된 "보이는" 크기를 반환하기 때문에, 측정 시점에 그 슬라이드가 `is-active`(1.14배)인지
      기본 상태(.78배)인지에 따라 같은 슬라이드인데도 측정값이 들쭉날쭉했음. 트랜스폼에 영향받지 않는
      레이아웃 폭(`offsetWidth`)으로 바꿔 해결 — 이제 어떤 슬라이드가 활성 상태든 항상 정확히 중앙.
    - **버그 2 — 가운데 슬라이드 위쪽이 직각으로 잘리던 것**: `.lookbook__track`에 `overflow-x:auto`만
      주고 `overflow-y`를 지정하지 않으면, "두 축 중 하나만 non-visible이면 나머지 축도 자동으로
      `auto`가 된다"는 CSS 스펙 규칙 때문에 세로도 암묵적으로 클리핑됐음 — 가운데 슬라이드가
      `scale(1.14)`로 커질 때 위아래로 튀어나온 부분(라운드 모서리 포함)이 그대로 잘려 나가 직각처럼
      보였던 것. `.lookbook__viewport`에 확대분을 충분히 덮는 세로 padding(44px~64px)을 줘서 애초에
      잘릴 내용이 없게 해결 — 모든 슬라이드가 항상 완전한 둥근 사각형(같은 박스, scale만 다름)으로
      보이므로 "모양이 안 맞다"는 지적도 같이 해소됨.
    - **버그 3 — 마우스 휠로 페이지 스크롤할 때 슬라이드가 반응하던 것**: 원인은 `overflow-x:auto`인
      요소 위에서 마우스 휠(세로 입력)을 돌리면 일부 브라우저가 그 세로 입력을 가로 스크롤로 떠넘기는
      동작 — 페이지를 스크롤하려던 휠 입력이 슬라이더 내부 스크롤 위치를 멋대로 바꿨음. 새 구조는
      뷰포트가 `overflow-x:hidden`일 뿐 스크롤 가능한 축 자체가 없어(위치는 전부 transform으로만 바뀜)
      휠이 항상 페이지 스크롤로만 쓰임 — 구조적으로 재발 불가능.
    - **가운데-나머지 대비 강화 + 화려한 전환**: 거리 기반 연속 보간(2차) 대신 활성(`is-active`)/
      인접(`is-near`)/비활성(기본) 3단계로 나눠 scale(1.14 / .92 / .78)·opacity·blur·그림자 차이를
      뚜렷하게 키우고, cubic-bezier(`.16,1,.3,1`, "expo-out") 이징으로 전환에 탄력을 줌.
    - **마우스 드래그 + 터치 스와이프 통합**: 2차의 `mousedown`/`mousemove`(마우스 전용) 대신 Pointer
      Events로 다시 구현 — 마우스·터치·펜이 전부 같은 코드 경로를 타므로 터치 스와이프도 별도 분기 없이
      동작. 드래그 중 `transform`을 1:1로 따라가다가(전환 애니메이션 꺼짐), 손을 떼면 이동 거리로 몇
      칸 넘어갔는지 계산해 가장 가까운 인덱스로 애니메이션과 함께 스냅.
  - **4차(같은 날): "1번이 화면 가운데가 아니라 왼쪽에 쏠려 비어 보인다, 처음부터 3개를 놓고 가운데부터
    보여주면 되잖아, 활성 슬라이드 그림자가 옆 슬라이드 위에 선처럼 걸쳐 보인다, 대비를 더 명확하게" —
    끝단 슬라이드 피크용 복제 + 스케일·그림자 재설계:**
    - **"중앙 정렬인데 한쪽만 비어 보이던" 문제의 정체**: 3차 수식은 실측 오차 0.03px로 수학적으로
      정확히 중앙 정렬이었음 — 문제는 수식이 아니라 "맨 앞/맨 뒤 슬라이드는 애초에 피크할 이웃이 한쪽에
      없다"는 사실 자체였음. 초광폭 모니터에서 640px 슬라이드 하나를 화면 정중앙에 두면 반대편엔 수백~
      1000px 가까운 완전한 빈 공간이 남는데, 이게 "정중앙인데 한쪽만 횅하다"는 인상을 준 것. 해결은
      `js/main.js`가 마지막 슬라이드의 복제본을 트랙 맨 앞에, 첫 슬라이드의 복제본을 맨 뒤에 장식용으로
      붙이는 것(`aria-hidden="true"`, `pointer-events:none`로 클릭·포커스 불가) — 이러면 1번이 활성이어도
      왼쪽엔 "5번의 복제본"이, 5번이 활성이어도 오른쪽엔 "1번의 복제본"이 피크해서 어떤 인덱스에서도
      항상 피크-활성-피크 3장 구도가 유지됨("3개를 놓고 가운데부터 보여달라"는 요청 그대로). 실제
      인덱스·점·화살표 네비게이션은 여전히 진짜 5장 기준으로만 동작 — 복제본은 순수 시각 장식.
    - **그림자가 옆 슬라이드 위에 선처럼 걸치던 버그**: 활성 스케일이 1.14배로 너무 커서 이웃 슬라이드
      영역까지 물리적으로 겹쳤는데, 활성의 `z-index`가 더 높아 그 위에 그려진 그림자가 이웃 카드
      표면 위로 그대로 얹혀 경계선처럼 보였던 것. 활성 스케일을 1.14→1.02로 낮춰(자기 박스 대비 거의
      그대로라 겹침이 사실상 사라짐) 근본 원인을 없애고, 그림자도 `spread`를 음수로(`-12px`~`-14px`)
      줘서 박스 경계에 바싹 붙게 축소.
    - **대비 강화("셀렉은 줄이고 나머지는 더 줄여라")**: 활성(1.14→1.02)은 오히려 줄이고 비활성은
      더 줄여서(기본 .78→.6, 인접 .92→.75) "절대 크기"가 아니라 "활성/비활성 배율 차이"로 대비를 키움
      — 활성이 비활성(기본) 대비 약 1.7배 커 보여, 활성 자체를 키웠던 이전보다 체감 대비는 오히려 더 큼
      (+부수 효과로 활성이 작아진 만큼 이웃과의 겹침도 줄어 그림자 버그와 동시에 해결).
    - 슬라이드 사이 `gap`도 24px→32px(모바일 16px→20px)로 넓혀 스케일 전환 중에도 여유를 더 줌.
  - **5차(같은 날): "간격이 안 맞는다, 처음부터 한 화면 안에 깔끔하게 맞추라고, 그게 안 되면 타이틀을
    좌측에 고정하고 우측에 슬라이드를, 첫(활성) 슬라이드는 크게 나머지는 작게" — 3~4차의 "가운데 정렬
    캐러셀 + scale 확대 + 복제 피크" 구조를 전부 폐기하고 좌/우 2단 레이아웃으로 재설계:**
    - **근본 원인 재진단**: 4차까지는 "정확히 뷰포트 중앙에 정렬"이라는, 숫자 하나라도 어긋나면 바로

      보이기 쉬운 구조였고, 사용자가 손으로 그려 보여준 "간격이 안 맞는다"는 바로 이 지점. 문제를
      더 정교한 수식으로 푸는 대신, "정중앙 정렬"이라는 요구 자체를 없애는 쪽으로 구조를 바꿈.

      움직임 — 사용자가 요청한 "타이틀 좌측 고정, 우측에 슬라이드" 그대로.

      왼쪽 끝에 딱 붙이기"(`offset = -activeSlide.offsetLeft`)로 변경. 인덱스가 0이면 offset도 정확히
      0이라 첫 슬라이드는 처음부터 여백 없이 왼쪽 끝에 딱 맞게 시작 — 양 끝 슬라이드가 "한쪽만 비어
      보이는" 문제 자체가 구조적으로 발생할 수 없고, 복제 피크 슬라이드도 더 이상 필요 없어져 js가
      훨씬 단순해짐.
    - **크기 차이를 scale이 아니라 실제 width/height로**: `transform: scale()`은 자기 flex-box 영역
      밖으로 물리적으로 튀어나와 이웃과 겹쳤고, 그게 4차에서 고친 "그림자가 선처럼 걸치는" 버그의
      원인이었음. 이제 활성 슬라이드는 실제 width/height 자체가 커지고(210×280 → 480×540px), flex가
      그 실제 레이아웃 크기를 기준으로 이웃을 밀어내며 재배치하므로 물리적 겹침 자체가 없음 — 그림자
      겹침·모서리 클리핑류 버그가 구조적으로 재발 불가능해짐("첫 슬라이드는 크게, 나머지는 작게"라는
      요청도 scale이 아닌 실제 크기 차이로 구현되어 더 명확하게 체감됨).
    - 모바일(900px 이하)에서는 좌/우 2단이 들어갈 폭이 없어 `.lookbook__layout`을 세로로 쌓음(타이틀 →
      화살표/점 → 슬라이더).

      간격을 뒀는데(예: rank0 `left:48,width:460`→끝 508, rank1 `left:178,width:300`→끝 478),
      `step(130)`이 이전 카드 너비(460)보다 훨씬 작다 보니 뒤 카드의 오른쪽 끝(478)이 앞 카드의
      오른쪽 끝(508)보다 더 안쪽에 들어와 **완전히 가려져 전혀 안 보이는** 카드가 됐음(실제로
      2560px 테스트에서 rank1이 화면에 전혀 안 보였음). **"각 랭크의 오른쪽 끝이 이전 랭크의 오른쪽
      끝보다 `peek`만큼 더 나가야 한다"는 식으로 뒤집어서 계산**(`end[n] = end[n-1] + peek[n]`,
      `left[n] = end[n] - width[n]`) — peek을 110→90→70→50px로 점점 줄여 바깥쪽 카드일수록 조금만
      삐져나오게. 최종값: rank0 `left:48`(끝508) → rank1 `left:318`(끝618, 110px peek) → rank2
      `left:498`(끝708, 90px peek) → rank3 `left:628`(끝778, 70px peek) → rank4(잔상) `left:718`
      (끝828, 50px peek).
    - **더 이상 `right`/`calc(100%...)`를 쓰는 랭크가 하나도 없어짐**: 전 랭크가 `.lookbook__slider`
      왼쪽 경계(=타이틀이 끝나는 지점) 기준 고정 px 하나로만 정해지므로, 9차에서 확인한 "left는
      해상도 무관하게 flex가 알아서 계산해주는 기준점"이라는 특성이 스택 전체에 적용됨 — 1800px·
      2560px 둘 다 실측으로 동일한 모양(`gapFromSlider` 48px로 동일) 확인.
    - **중간 구간(901~1300px)**: 기본 구간 간격을 그대로 ~76% 비례 축소하면 901px(이 구간 하한)에서
      rank1(또렷해야 할 중요한 카드)까지 심하게 클리핑되는 걸 계산으로 확인 — peek 값 자체를 더
      압축(70/55/40/30px)해서 독립적으로 다시 튜닝, 901px에서도 rank0·1 핵심 카드는 거의 온전히
      보이고 rank3·4(잔상)만 살짝 잘리는 정도로 완화.

      있었고, 이번 피드백의 스크린샷은 와이드 데스크톱 기준이었음).

    화면 가득찼으면 좋겠어. 잔상을 늘리든 사이즈를 키우든 컨테이너에 갇힌 섹션이 아니라 자유롭게 하나의
    화면이 될 수 있게"** — 10차가 고정 px로 박아둔 탓에 생긴 "화면이 넓어져도 카드는 제자리, 오른쪽만
    빈 여백" 문제를 비례 분산으로 재설계:
    - **진단**: 10차의 `left` 값(48/318/498/628/718px)은 전부 고정 px — 2560px 실측 결과 마지막 카드
      (rank4) 오른쪽 끝이 뷰포트 오른쪽 끝에서 556px나 떨어져 있었음. 9차에서 겪었던 것과 본질적으로
      같은 문제(해상도가 커져도 안 늘어나는 고정값)가 이번엔 전체 스택에 재발한 것.
    - **해법 — 슬라이더 폭 비례 균등 분산**: rank0(타이틀 바로 옆, 기준점)만 `left: 48px` 고정으로
      남기고, rank1~4는 "각자의 오른쪽 끝(`left+width`)이 rank0 끝(508px)에서 슬라이더 오른쪽 끝(
      `100% - 40px`)까지를 4등분한 지점에 오도록" 역산 — `end[n] = 508px + n/4 * (100% - 548px)`
      (n=1~4, 548 = 508 + 우측 여백 40). `left[n] = end[n] - width[n]`을 `calc()`로 표현하면
      rank1 `calc(71px + 25%)` / rank2 `calc(24px + 50%)` / rank3 `calc(75% - 53px)` / rank4
      `calc(100% - 150px)`. 네 구간의 "끝" 간격이 모두 `0.25 * 슬라이더폭 - 137px`로 같아서(대수적으로
      네 식이 전부 동일한 선형 증분을 가짐) 9~10차처럼 특정 카드 하나만 뚝 떨어져 보이는 섬 현상이
      생기지 않음 — 대신 화면이 넓을수록 카드 사이 간격이 다같이 넓어지며 점점 흩어지는 모양이 되어
      "자유롭게 퍼지는" 느낌 자체가 강화됨. rank4의 끝은 항상 슬라이더 폭의 정확히 40px 안쪽이라
      1800px·2560px 둘 다 실측으로 거의 뷰포트 우측 끝까지 닿는 것을 확인.

      클래스가 재발할 수 없음. 901~1300px 중간 구간과 모바일(≤900px)은 애초에 고정 px라도 슬라이더
      자체 폭이 좁아 카드들이 거의 다 겹치며 공간을 꽉 채우고 있어 같은 문제가 없었으므로 이번 라운드

   두껍게 줘도 안 보이는 게 당연했음(스트로크 두께 문제가 아니라 "밝은 배경+밝은 색" 자체가 원인 — 52차
   진단 자체가 틀렸었음). **수정**: 채우기를 본문과 같은 `--ink`(항상 대비 보장)로 바꾸고, volt는
   `-webkit-text-stroke`가 채우기 아래 깔리는 특성을 이용해 글자 바깥쪽에 얇은 림(rim)으로만 비치게 함
   (`color:var(--ink); -webkit-text-fill-color:var(--ink); -webkit-text-stroke:3px var(--volt)`) —
   "가독성은 본문과 동일 + 포인트컬러는 아웃라인으로" 두 요구를 동시에 만족(css `.manifesto__text em` 참고).
2. **BY THE NUMBERS 제거**: "위치가 애매하다"는 피드백으로 41~52차에 걸쳐 다듬어온 `.specs`/`.spec-card`
   섹션(41차 흰 박스→43차 복귀→52차 박스 제거+재배치 등 여러 차례 반복 조정했던 바로 그 블록)을 통째로
   삭제. 이 섹션 전용이었던 PRODUCT의 3단계 핀+스크럽(42차)도 함께 2단계로 축소(html 마커 3개→2개,
   css의 `[data-stage="3"]` 분기 전부 `"2"`로 병합) — 스크롤해도 더 이상 빈 단계가 남지 않음. js의
   숫자 카운트업(`[data-count]`)·`numPop` 키프레임 등 이 섹션 전용 코드도 함께 제거(더 이상 참조하는
   엘리먼트가 없어 완전히 죽은 코드였음).
3. **룩북 실사 이미지 5장 + 흑백→컬러 호버**: 사용자가 보내준 6세트(세트당 컬러+흑백 쌍, 총 12장) 중
   신발·브랜드 포인트가 약한 "플랫레이(카메라·칼·식물)" 세트를 빼고 5세트 선정 — 스케이트보더(STREET),
   스트레칭하는 모습(기존 TRACK 자리 → 어울리는 사진이 없어 **TRAINING**으로 테마 교체),
   스우시 자수 매크로(STUDIO, "디테일이 말하는 완성도" 설명과 가장 잘 맞음), 나란히 놓인 스니커즈
   (기존 NIGHT RUN 자리 → 밤 러닝 사진은 받지 못해 **COLLECTION**으로 교체), 테니스 코트 위 신발+라켓
   (COURT). 받지 못한 테마(밤 러닝 등)에 사진을 억지로 끼워맞추지 않고, 실제 사진에 맞게 패널 이름/설명을
   새로 씀 — html 주석·위 53차 커밋 참고.
   - **흑백→컬러 전환 가능 여부**: 가능함. 사용자가 흑백 버전도 같이 보내줬지만 두 이미지를 겹쳐
     크로스페이드하는 대신, **컬러 원본 한 장**에 `filter: grayscale(1)`을 기본으로 걸어두고 호버/탭/
     키보드 포커스 시 `grayscale(0)`으로 전환(`transition: filter .8s ease`) — 이미지 로드 1장으로
     끝나 더 가볍고, 기존 아코디언의 호버/`.is-active`/`:focus-visible` 트리거를 그대로 재사용할 수
     있어 새 JS가 전혀 필요 없었음. 레이어 순서는 사진(z-index:0) → 기존 하단 그라데이션(1, 텍스트
     가독성용) → 라벨/디테일 텍스트(2)로 명시적으로 고정.
   - **모바일 탭 버그 발견 및 수정(기존부터 있던 버그)**: 이미지를 넣고 모바일 탭을 테스트하다가,
     패널을 탭해도 거의 안 커지는(실측 0.67px) 기존 버그를 발견 — 원인은 데스크톱 전용
     `.lookbook__panel.is-active, :focus-visible { flex:7 1 0% }`(클래스 2개, specificity 0-0-2-0)가
     미디어쿼리와 무관하게 모바일 블록의 `.lookbook__panel { flex:none }`(클래스 1개, 0-0-1-0)보다
     우선순위가 높아 그대로 새어 들어온 것 — 모바일 블록이 `height:360px`만 덮어쓰고 `flex`는 안
     건드려서, 탭한 패널이 `flex-grow:7`인 채로 column flex 컨테이너(이미 나머지 4개 패널의 고정
     84px 합계로 꽉 차 여유 공간이 거의 없음)에 들어가 거의 0px로 짜부라졌던 것. 모바일 블록에
     `flex:none`을 명시적으로 같이 줘서(동일 specificity, 소스 순서상 뒤라 승리) 해결 — 실제 폰(375px)
     에서 탭 시 360px로 정상 확장되는 것까지 확인.
