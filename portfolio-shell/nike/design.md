# Design Guide — nike 프로젝트

> 이 문서는 이 프로젝트의 디자인 기준이다.
> 모든 화면과 컴포넌트는 이 문서를 먼저 읽고 따른다. 규칙과 어긋나면 만들기 전에 멈추고 물어본다.

## 1. Overview
- 성격: **포트폴리오용 비주얼 케이스스터디** (실제 서비스 아님, 데이터 없음)
- 컨셉: 나이키 브랜드를 소재로 한 **가상 캠페인/컨셉 랜딩 페이지** — 2021년식 jQuery 클론 사이트(구버전)를
  대체하는 완전히 새 디자인. "나이키라면 이런 캠페인 페이지를 만들었을 것 같다"는 톤.
- 브랜드명·워드마크는 나이키를 그대로 쓰되(이름 새로 짓지 않음), **스우시 로고 이미지 자산은 복제하지 않는다**
  (상표 이미지 그대로 베끼는 건 피하고, 워드마크는 타이포그래피로 직접 구현).
- 제품 비주얼: 지금은 **추상 그래픽(그라데이션·도형)**으로 채움. 실제 신발 사진/목업은 **사용자가 나중에 직접
  구해서 교체**(코드에 플레이스홀더 교체 지점을 명확히 주석으로 남길 것).
- 구성(원페이지): 히어로 → 매니페스토(짧은 선언문) → 제품 쇼케이스(스크롤 인터랙션) → 기능 하이라이트 →
  룩북 갤러리 → CTA(드롭 알림 신청, 실제 전송 없음) → 푸터

## 2. Colors
`css/style.css`의 `:root` 토큰이 단일 소스.

| 역할 | 토큰 | 값 |
|---|---|---|
| Ink(기본 배경, 히어로/CTA) | `--ink` | `#0A0A0A` |
| Ink 2(다음 톤, 카드 등) | `--ink2` | `#171717` |
| Paper(밝은 섹션 배경) | `--paper` | `#FFFFFF` |
| Paper muted(연한 회색 섹션) | `--paper2` | `#F5F5F5` |
| 포인트(액센트, CTA·하이라이트) | `--volt` | `#D7FF3E` |
| 본문(밝은 배경 위) | `--text` | `#111111` |
| 보조 텍스트(밝은 배경) | `--muted` | `#6B6B6B` |
| 본문(어두운 배경 위) | `--text-on-dark` | `#F5F5F5` |
| 보조 텍스트(어두운 배경) | `--muted-on-dark` | `#9A9A9A` |
| 경계선(밝은 배경) | `--border` | `#E6E6E6` |

- **흑백 대비가 기본 언어**: 섹션 단위로 완전한 블랙 또는 완전한 화이트를 쓰고, 중간 회색 배경은 최소화.
- **Volt(네온 옐로우그린)는 CTA·강조 한 곳에만** — 남용 금지(포인트 색이 희석되면 효과 없음).
- 컬러 사진/목업을 나중에 넣을 때도 이 톤(고대비 흑백 + volt 포인트)에서 크게 벗어나지 않게.

## 3. Typography
- **디스플레이(헤드라인)**: `Oswald`(Google Fonts, condensed bold) — 나이키 특유의 압축된 임팩트 서체 톤을
  웹폰트로 근사. 전부 대문자 + 넓은 letter-spacing 금지(오히려 타이트하게, -0.01~-0.02em).
- **본문**: `Pretendard`(한국어) — 다른 프로젝트와 동일 소스, 로딩 중복 없음.
- H1(히어로) 96px / 800 / line-height 0.95 (모바일 56px)
- H2(섹션 제목) 56px / 700 / line-height 1.0 (모바일 36px)
- 본문 16–18px / Pretendard Regular~600 / line-height 1.6
- 라벨/키커 13px / 700 / letter-spacing .08em / 대문자

## 4. Layout & Spacing
- 8px 그리드. 콘텐츠 최대 너비 1200px, 좌우 여백 24px(모바일 20px).
- 섹션은 **풀블리드(배경은 뷰포트 전체)** + 내부 콘텐츠만 1200px 정렬.
- 섹션 간 경계는 색 대비(흑/백 전환)로 구분 — 카드 테두리·그림자 남용 금지.

## 5. Motion
> **2026-10-19 1차**: "가뿐처럼 절제된 톤"이 아니라 화려하고 인터랙션이 강한 톤으로(사용자 지시). 커스텀 커서·
> 마그네틱 버튼·3D 틸트를 추가했으나 → **사용자 피드백: "살짝 과함, 인터랙션을 다 때려넣은 느낌. 원한 건 디테일보다
> 전체적인 화려함 — 큼직큼직하고 스크롤링에 따른 변화."** 즉 마우스 정밀도에 의존하는 "디테일 레이어"를 여러 개
> 겹치는 게 아니라, **스크롤에 반응해 화면 전체가 크게 움직이는 적은 수의 임팩트 있는 연출**을 원함.
>
> **2026-10-19 2차(현재 방향)**: 커스텀 커서·마그네틱 버튼·3D 틸트 **제거**. 대신 스크롤 스크러빙 기반의
> 큰 전환 효과에 집중.

- 스크롤 등장: 아래→위 페이드업(`opacity 0→1, translateY 40→0`), `IntersectionObserver` 1회 트리거(기본 베이스는 유지).
- **스크럽 스무딩(2026-10-19 1차, "효과가 더 부드러웠으면" 피드백):** 히어로 줌아웃·매니페스토 핀드줌·쇼케이스 비주얼
  스크럽 전부, 실제 `scrollY`를 바로 쓰지 않고 **lerp로 보간한 `smoothY`**를 공통으로 사용(가뿐 히어로 패럴럭스의
  lerp(0.09)와 동일 패턴). 계산 기준도 `getBoundingClientRect`(매 프레임 레이아웃 재계산 필요) 대신
  `offsetTop`/`offsetHeight`를 `resize`에 한 번만 캐시해두는 방식으로 바꿔 성능도 더 가벼워짐.
  ⚠️ **2차(같은 날, "섹션 전환·폰트 애니메이션이 딱딱 끊김" 추가 피드백):** lerp(0.085)만으론 부족 — 원인 둘 더 찾음:
  ①`.grain`(필름 질감 오버레이)의 `mix-blend-mode: overlay`가, 그 아래 레이어가 매 프레임 스크럽으로 바뀔 때마다
  블렌드 영역 전체 재합성을 유발해 스크롤 중 프레임이 끊겼음 → blend-mode 제거(opacity만으로 유사 효과 유지).
  ②lerp 계수를 0.085→**0.06**으로 낮춤(더 천천히 따라가게) — 마우스 휠처럼 값이 듬성듬성 들어오는 입력에서도
  개별 틱이 뭉개져 보이도록. ③스크럽 대상 요소(`.hero__inner`, `.manifesto__text`, 쇼케이스 SVG)에
  `backface-visibility: hidden` 추가해 GPU 레이어 합성을 더 안정적으로(폰트 서브픽셀 흔들림 완화 목적).
- **히어로 키네틱 타이포**: "NIKE" 4글자를 개별 `span`으로 쪼개 글자마다 다른 지연으로 scale+rotate+blur-in(유지).
- **히어로 스크롤 줌아웃(유지)**: 스크롤을 시작하면(0~1 viewport height 구간) 히어로 콘텐츠가 `scale` 커지면서
  `opacity` 빠지는 줌 통과 전환. `hero-wrap`(200vh)이 스크롤 공간을 주고 `.hero`는 그 구간만 sticky.
  ⚠️ **2026-10-20 시행착오**: "섹션 전환이 밋밋하다"는 피드백을 "다음 섹션이 이전 섹션 전체를 덮어야 한다"로
  잘못 해석해서, 한때 `.hero`를 바운드 없는 sticky(영구 고정)로 바꾸고 `.manifesto`가 전체를 덮어 올라오게
  만든 적이 있었음 → **"그 인터랙션(줌아웃) 좋았는데 왜 뺐냐, 전체를 덮으라는 게 아니라 배경만 attachment
  느낌을 달라는 거였다"는 피드백으로 되돌림.** 줌아웃은 그대로 복원하고, 실제 요청은 아래 "배경 패럴럭스"로 해결.
- **배경 패럴럭스("background-attachment" 느낌, 2026-10-20):** 섹션 전체가 아니라 **배경 레이어만** 콘텐츠와
  다른 속도로 움직여서 전환에 깊이감을 줌 — 전체를 덮는 과장된 연출이 아니라 은은한 터치.
  - `.manifesto__bg`/`.showcase__bg`: 가뿐 히어로 패럴럭스와 동일한 공식 `translateY(-(요소중심−뷰포트중심)*speed)`를
    `data-speed`(각각 0.15 / 0.2)로 적용. 이 두 섹션은 보통 문서 흐름으로 스크롤되므로(내부에 sticky 핀/비주얼만
    있고 섹션 자체는 sticky 아님) 뷰포트 안에서 위치가 바뀌어 이 공식이 정상 작동함(실측: scrollY 1400에서
    `.manifesto__bg`가 `translateY(-7.6px)`로 변함 — 확인됨).
  - `.hero__bg`: `.hero` 자체가 sticky로 고정돼 있어 뷰포트 기준 위치가 안 바뀌므로 같은 공식이 성립하지 않음
    (실측 결과 `translateY(0px)` 고정 — 패럴럭스 없음을 직접 확인하고 교체). 대신 **히어로 progress에 직접
    바인딩해 배경을 전경보다 훨씬 느리게 확대**(배경 `scale(1→1.15)` vs 전경 `scale(1→1.9)`) — "배경은 거의
    제자리, 콘텐츠만 그 위를 빠르게 지나간다"는 동일한 체감을 다른 방식으로 구현.
- **매니페스토 핀드 줌텍스트**: 섹션을 2.2배 높이(`220vh`)로 늘리고 텍스트를 `sticky`로 중앙 고정, 그 구간 스크롤
  진행률에 따라 텍스트가 `scale(0.5→1.15)`로 커지며 등장 — 큰 스크롤텔링 연출(Awwwards에서 흔한 "핀 텍스트 줌" 기법).
  **2026-10-20 조정**: 같은 "핸드오프가 급작스럽다" 문제가 2→3 전환(매니페스토→쇼케이스)에도 있었음 — progress가
  sticky 해제 시점과 정확히 동시에 1.0에 도달해 "확대 완료 = 곧바로 스크롤아웃"이었음. **progress 계산을
  `range*0.75`로 나눠 75% 지점에서 이미 확대 완료**시키고, 나머지 25% 구간은 완전히 확대된 채로 "멈춰 있다가"
  쇼케이스(검정)가 자연스럽게 덮어오도록 호흡을 줌.
- **스크롤 스크러빙(제품 쇼케이스)**: 1회성 reveal이 아니라, 섹션 스크롤 진행률(0~1)에 실시간으로 바인딩해서 비주얼이
  계속 회전(`rotate`)·확대(`scale`)·글로우 강도가 변함 — Apple 제품 페이지처럼 "스크롤이 곧 애니메이션 타임라인"(유지).
- **스펙 숫자**: 뷰포트 진입 시 `scale(0.3)+blur`에서 오버슈트 있는 큰 팝업(elastic) + 0→실제값 카운트업. 작은
  페이드가 아니라 "쾅" 하고 등장하는 느낌.
- **룩북 타일**: 뷰포트 진입 시 `clip-path`가 한쪽에서 다른 쪽으로 크게 와이프되며 열림(단순 fade 아님).
- **마퀴 텍스트 밴드**: 매니페스토~쇼케이스 사이에 큰 글씨가 좌→우 무한 스크롤되는 띠(유지, "JUST MOVE —" 반복).
  장식용(`pointer-events:none`, `aria-hidden`), 가뿐의 인기 여행지 티커와 같은 구현 패턴(세트 2번 렌더).
- **그레인 텍스처**: 어두운 섹션에 은은한 필름 그레인 오버레이(유지).
- `prefers-reduced-motion: reduce`면 **위 전부** 즉시 최종 상태로(스크러빙·핀드줌·줌아웃·카운트업·와이프 전부
  비활성화/즉시 완료 상태, 마퀴는 정지) — 기존 프로젝트들과 동일 규칙.

## 6. Components
- **히어로**: 블랙 배경, 중앙 또는 좌측 정렬 큰 워드마크 "NIKE"(또는 캠페인 문구) + 짧은 태그라인 + 스크롤 유도.
  배경에 volt 톤 그라데이션 블롭(은은하게, 장식).
- **매니페스토**: 화이트 배경, 큰 타이포(28~40px) 1~2문장. 이미지 없음 — 타이포그래피 임팩트로 승부.
- **제품 쇼케이스**: 블랙 배경, 좌 스티키 추상 비주얼(그라데이션 도형 — `<!-- PLACEHOLDER: 실제 제품 목업 이미지로 교체 -->` 주석) / 우 스크롤 피처 리스트.
- **기능 하이라이트**: 화이트 배경, 3~4개 카드(아이콘 없이 큰 숫자/키워드 중심, 미니멀).
- **룩북 갤러리**: 비균등 그리드(일부 칸 크게), 각 칸은 그라데이션 placeholder + `data-placeholder` 속성으로
  "실제 이미지 교체 지점"임을 명확히 표시. hover 시 살짝 확대.
- **CTA**: volt 배경 또는 블랙+volt 텍스트, 이메일 입력(목업, 실제 전송 없음 — 제출 시 "신청 완료" 텍스트만 토글).
- **푸터**: 미니멀, 블랙.

## 7. Responsive
- 단일 브레이크포인트 900px: 그리드 1열, 폰트 축소(위 Typography 참고), 제품 쇼케이스는 스티키 해제하고
  세로로 비주얼 → 피처 리스트 순서 배치.

## 8. 플레이스홀더 규칙(중요)
- 실제 이미지가 들어갈 자리는 전부 **그라데이션 SVG/CSS 도형**으로 채우고, 코드에 `<!-- PLACEHOLDER -->` 주석과
  `.ph-visual` 류의 명확한 클래스명을 달아, 나중에 사용자가 `<img>`로 교체하기 쉽게 한다(가뿐/shell 프로젝트와
  동일 패턴 — design.md나 CLAUDE.md의 "인라인 style 금지, 플레이스홀더는 명확히" 관례 따름).
