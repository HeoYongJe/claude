# design.md — yjportfolio.co.kr 메인(shell)

이 프로젝트에서 디자인·UI 작업을 할 때는 이 파일을 먼저 읽고 규칙을 따른다(CLAUDE.md 참고).
규칙과 어긋나는 요청이 들어오면 만들기 전에 멈추고 사용자에게 먼저 물어본다.

## 디자인 톤
- 다크 테마(`--bg:#070a11`), 포인트 컬러는 블루 계열(`--blue` 그룹, `styles.css` `:root` 토큰).
- 장식은 과하지 않게 — 히어로의 글래스 카드 구성·회로 SVG 등 기존 톤을 해치지 않는 선에서 추가한다.

## 기존 구조(참고)
- `script.js`: 프리로더(0→100% 카운터 후 제거) + 스크롤 진행바 + 자체 구현 스무스 스크롤(휠
  가로채서 lerp) + `[data-reveal]` IntersectionObserver 리빌 시스템. 새 기능을 더할 땐 이
  프리로더/스크롤 체계와 충돌하지 않게(특히 프리로더가 완전히 걷힌 뒤에 시작하도록) 주의.
- `.yj-hero-visual`(글래스 카드 7장 + SVG 회로 연결선)은 `max-width:960px`에서 `display:none`
  — 새로 추가하는 데스크톱 전용 장식도 이 기준(961px)을 따른다.

## 변경 이력

- **"에이전트 코드" 인트로(2026-11-10, `agentIntro.js`)**: 사용자가 saai.pro 참고 스크린샷(피그마류
  협업 커서+리사이즈 핸들+W×H 치수 배지)을 보여주며, 원래는 가뿐(travel)에 적용했다가 "그게
  아니라 셸 메인에 적용하고 싶었다"고 정정 — 가뿐 버전은 원복(태그 없이 그냥 커밋으로),
  셸에는 핵심 메커니즘을 더 정확히 구현: "요소가 숨겨져 있다가, 커서가 박스를 그린 뒤 그 안에서
  콘텐츠가 타이핑되듯 순차적으로 나타남"(가뿐 버전은 이미 보이는 요소 위에 박스만 씌웠던 것과
  다름).
  - **대상**: 히어로의 eyebrow·타이틀·서브(실제 텍스트, 타이핑으로 복원) + 글래스 카드 7장
    (장식용 목업, 박스 완성 후 페이드+스케일로 등장). nav·CTA 버튼은 항상 보이고 조작 가능하게
    유지(인트로 중에도 다른 페이지로 이동 가능해야 하므로 숨기지 않음).
  - **타이핑 구현**: 중첩 태그(`<em>`/`<span class="yj-hero__title-accent">`)와 `<br>`를 그대로
    보존한 채 재귀적으로 한 글자씩 타이핑(`typeInto`) — 끝나면 원본과 100% 동일한 DOM이라
    접근성 텍스트 손실 없음. 박스 치수는 "지우기 전" 원본 텍스트의 실측 rect를 써서 정확함
    (지운 뒤 다시 채워지는 동안 일시적으로 줄 수가 달라져도 박스 크기 자체는 최종 크기를 미리
    보여주는 게 의도된 연출).
  - **에이전트 3개(색상)**: 파랑(`--blue`, 텍스트 3개 타이핑), 블루소프트(`--blue-soft`, 카드
    앞 4장 페이드), 바이올렛(`rgb(167,139,250)`, 나머지 카드 3장 페이드) — 병렬 실행, 서로 다른
    시작 지연(300/650/1000ms)으로 자연스럽게 겹침.
  - **시작 시점**: 프리로더(`#yj-preloader`)가 DOM에서 완전히 제거된 걸 `MutationObserver`로
    감지한 뒤에만 시작(하드코딩된 타이밍 의존 안 함, 6초 안전장치 포함).
  - **가드**: `innerWidth<961`(기존 `.yj-hero-visual{display:none}` 기준과 통일)이면 전부
    스킵 — 이 경우 요소들을 애초에 숨기지도 않아 평소처럼 즉시 보임. `prefers-reduced-motion`
    이면 비활성화.
  - **로컬 검증**: 프리로더 종료 수 초 후 타이틀이 중첩 `<em>` 색상(`--blue-mid`)과 `<br>` 줄바꿈
    그대로 타이핑 복원된 것 확인, 카드들이 동시에 각기 다른 타이밍으로 페이드인되는 것 확인
    (한 프레임엔 일부만 완전히 불투명, 일부는 전환 중인 상태 포착), 콘솔 에러 없음, 800px(모바일
    기준 폭)에서는 숨김 자체가 적용 안 돼 텍스트가 즉시 보이는 것(기능 자체가 스킵됨) 확인.

- **전체 페이지 버전으로 확장(2026-11-11)**: 위 히어로 전용 버전에 대해 사용자가 세 가지 재지적:
  "모든 섹션·모든 요소에 적용 가능한가", "더 정확하고 빠르게(박스 위치가 요소에서 어긋남, 느림,
  일부만 적용돼 일관성 없음)". 추가로 "한 번에 다 나오는 게 아니라 히어로 완성→02 섹션으로
  자동 스크롤→완성→03→…→마지막 섹션까지 완성되면 맨 위로 자동 스크롤, 처음엔 완전히 빈
  화면에서 시작"하는 전체 페이지 시네마틱으로 확장 요청.
  - **원인 진단(박스 어긋남)**: 글래스 카드 7장이 사는 `.yj-stage`가 `rotateX(11deg)
    rotateY(-18deg)`로 3D 회전+ `transform-style:preserve-3d`이고, 각 카드는 `translateY`
    둥실거림이 무한 반복(`animation:yjFloatA/B/C ... infinite`) — 뷰포트 기준 평면 사각형은
    기울어진 채 계속 움직이는 대상을 정확히 못 감쌈. **해결**: 그 카드들만 박스 "테두리"를
    같은 3D 부모(`.yj-stage`) 안에 로컬 좌표(`getComputedStyle`의 left/top/width/height,
    카드 자신과 동일한 좌표계)로 직접 그려 똑같이 회전하게 하고, 박스를 그리는 동안만
    `animationPlayState='paused'`로 둥실거림을 멈춤. 핸들·배지는 그려도 글자/점이 비스듬히
    눕지 않게 항상 뷰포트 좌표 유지(점 표시라 기울어진 요소에도 정확).
  - **"일부만 적용" 해결**: 손으로 요소를 고르는 대신, 사이트에 이미 체계적으로 붙어있던
    `[data-reveal]`(스크롤 리빌 단위)에 전부 `data-build`를 같이 붙이고(index.html), 히어로
    전용 요소(nav 로고·메뉴, eyebrow·타이틀·서브·CTA·글래스 카드 7장)에도 새로 `data-build`를
    붙여서 — 코드가 `[data-build]` 전체를 자동으로 순회(섹션별로 그룹화)하기 때문에 빠지는
    곳이 구조적으로 없음(44개 전부 opacity:1로 끝나는 것 실측 확인).
  - **타입 자동 분류**: 수동 표시 없이, 자식 요소 태그를 보고 판정(`BR/EM/SPAN/STRONG/B/I/A/
    SMALL`만 있으면 "타이핑", 그 외 블록 자식(DIV 등)이 하나라도 있으면 "통째로 페이드") —
    `.yj-work`·`.yj-step`·`.yj-principle`·`.yj-skillgroup`·`.yj-contact-card` 등 전부 이
    규칙 하나로 올바르게 분류됨(하드코딩 리스트 불필요, 직접 트레이스로 검증).
  - **속도**: 모든 타이밍을 대폭 단축(이동·박스확장 480→170ms, 홀드 850/650→200ms, 정리
    240→110ms, 타이핑 24→9ms/글자), 섹션당 동시 커서 수 3→4로.
  - **완전히 빈 화면에서 시작**: index.html 맨 위에 동기 인라인 스크립트 추가 — localStorage에
    `yjIntroSeen`이 없으면 `<html>`에 `yj-intro-pending` 클래스를 첫 페인트 전에 붙임.
    `styles.css`의 `html.yj-intro-pending [data-build]{opacity:0}`가 이 클래스를 보고 숨김 —
    기존 `[data-reveal]{opacity:0;...}`(무조건 적용) 규칙과 안 겹치게 조건부로 분리해서,
    재방문(클래스 없음)에선 이 규칙 자체가 안 걸려 완전히 기존 그대로 동작.
  - **섹션 순차 빌드 + 자동 스크롤**: nav+히어로 묶음 → think → works → principles → about →
    contact 순서로, 각 섹션 도착 시 `getBoundingClientRect()`를 그 자리에서 새로 읽어 스크롤
    (섹션 전환할 때마다 다시 재서 이전 섹션의 타이핑 중 일시적 레이아웃 변화에 영향 안 받음) →
    섹션 안 `[data-build]`를 병렬로 빌드 → 끝나면 다음 섹션. 마지막 섹션 끝나면 맨 위로.
  - **최초 1회만 + 건너뛰기**(사용자 선택): `localStorage.yjIntroSeen`으로 1회만 재생, 재방문은
    아무 처리도 안 해서 완전히 기존 사이트 그대로. 클릭·키 입력(휠은 막기만 하고 스킵 트리거는
    안 함)으로 즉시 전체 완성 상태로 점프(`forceFinishAll` — 레지스트리에 미리 저장해둔 원본
    HTML로 타이핑 요소 즉시 복원, 나머지는 opacity/transform 즉시 확정, 오버레이 제거, 맨
    위로 점프, 스크롤 잠금 해제, localStorage 기록).
  - **스크롤 잠금**: 기존 프리로더가 쓰던 `.yj-noscroll`(body `overflow:hidden`) 재사용 +
    휠·스페이스/방향키/PageUp·Down/Home·End·터치무브를 캡처 단계에서 `preventDefault`(우리
    쪽 `window.scrollTo` 프로그램 호출은 이 차단과 무관하게 그대로 동작).
  - **⚠️ 실제로 겪은 버그와 수정**:
    1. 모바일/좁은 화면·reduced-motion일 때 단순히 `return`만 하면 `html.yj-intro-pending
       [data-build]{opacity:0}`가 아무도 안 풀어줘서 **콘텐츠가 영원히 안 보이는 버그**(실측
       으로 발견 — 800px에서 title opacity가 계속 0으로 나옴) → 이 경우 `yj-intro-pending`
       클래스를 직접 제거하도록 수정. (단, `yjIntroSeen`은 기록하지 않음 — 나중에 데스크톱·
       motion 허용 환경으로 다시 오면 그땐 정상 재생되게.)
    2. **로컬 테스트 중 브라우저 캐시 함정**: `styles.css`/`script.js`/`agentIntro.js`에 버전
       쿼리스트링이 없어서, 코드를 고쳐도 브라우저가 이전 응답을 계속 재사용 — `document.
       styleSheets`의 실제 파싱된 규칙을 직접 검사해서(raw fetch로 가져온 텍스트와 대조)
       발견. `?v=20261111a` 식 쿼리스트링을 세 파일 모두에 추가해 해결 — 이후 수정마다
       버전을 올려야 함(가뿐 프로젝트와 같은 관례, 이 프로젝트엔 이번에 처음 도입).
  - **로컬 검증**: 전체 사이클 1회 실행 후 `[data-build]` 44개 전부 opacity:1 확인, 타이틀·
    Think 제목의 중첩 태그/`<br>` 원본 그대로 확인, 글래스 카드 로컬 박스 좌표가 해당 카드의
    CSS 선언값과 정확히 일치하는 것 확인(`.yj-glass--text`: left 55px/top 99px/width 158.74px
    = 27.3%·height 78px = 15.7%, 실측), 콘솔 에러 없음. 재방문(스크롤 0, `yjIntroSeen` 존재)
    → 즉시 완성 상태로 렌더 확인. 건너뛰기(1초 뒤 Escape) → 즉시 맨 위 완성 상태로 점프,
    `localStorage` 기록, 오버레이 제거, 스크롤 잠금 해제 확인.

- **"새로고침해도 재생 안 됨" + "순서가 뒤죽박죽" + 속도 재조정(2026-11-11)**:
  1. **매 방문마다 재생**: `localStorage`로 1회만 재생하던 걸 요청대로 제거 — index.html 맨 위
     인라인 스크립트가 조건 없이 매번 `yj-intro-pending`을 붙임. `agentIntro.js`에서도
     `markSeen`/`localStorage` 관련 코드 전부 제거.
  2. **"뒤죽박죽"의 진짜 원인(실측으로 확정)**: `scrollY`를 100ms 간격으로 샘플링해보니 0→824→
     900→2243→1431(!)→2782→2273(!)→3002 식으로 실제로 뒤로도 갔다 앞으로도 갔다 하는 것을
     직접 확인(샘플 192개 중 143개가 "뒤로 감" 판정) — 원인은 `afterPreloader`의 6초 안전장치
     `setTimeout`이 `MutationObserver`가 정상적으로 먼저 발동해도 취소가 안 돼서, 6초 뒤
     **전체 시퀀스가 통째로 한 번 더 겹쳐서 돌기 시작**했던 것(서로 다른 목표로 스크롤을
     다투니 화면이 왔다갔다). `done` 플래그 + `clearTimeout`으로 `cb()`가 정확히 한 번만
     불리게 수정. 수정 후 재실측: 203개 샘플 중 "뒤로 감" 3개뿐(그것도 2892→2947 같은 55px
     이내 흔들림, 복귀 스크롤 막바지의 자연스러운 보정) — 사실상 완전히 단조 증가 확인.
  3. **부가 원인(같이 수정)**: `script.js`의 기존 히어로 패럴랙스(`onScroll`)가 인트로가 자동
     스크롤로 히어로를 지나가는 구간에서 eyebrow/title/sub/visual의 opacity·transform을 동시에
     건드리고 있었음 — `yj-intro-pending` 동안은 이 패럴랙스를 끄도록 수정(히어로가 "이미
     완성했는데 다시 흔들리는" 것처럼 보이는 2차 원인이었을 가능성).
  4. **"여전히 미리 나와있는 요소"**: 히어로 배경 장식(`.yj-hero__dots`, `.yj-hero__glow`,
     `.yj-connectors` SVG)에 `data-build`가 안 붙어있어서 처음부터 계속 보이고 있었음 — 셋 다
     추가해 다른 요소들과 똑같이 숨김→빌드되게 함(`.yj-connectors`는 `.yj-stage` 안이라
     로컬 3D 박스 로직이 자동으로 적용됨, 별도 분기 불필요).
  5. **속도**: "너무 빠르다"는 재지적으로 모든 타이밍 값을 30~40%씩 늘림(예: 이동/박스확장
     170→230ms, 홀드 200→280ms, 타이핑 9→13ms/글자, 섹션 전환 스크롤 520→650ms) — 전체
     한 바퀴가 버그 수정 전(겹쳐 돌아 오히려 깨져 보이던) 체감과 달리, 고친 뒤 정상적인
     한 번짜리 실행으로 약 28초(2026-11-10 최초 버전의 20~30초 추정치와 비슷한 수준으로
     복귀 — 전 라운드의 "14초"는 버그로 겹쳐 돌다가 어중간하게 끝난 비정상 측정치였던 것으로
     보임).

### 네 번째 다듬기(같은 날, 2026-11-12 — 스크린샷에 빨간 O/X 표시로 피드백)
사용자가 라이브 스크린샷에 빨간 원(O, "여기에 ME")과 X 두 개("이건 치워줘")를 직접 그려서 보냄 +
"HTML/CSS가 너무 자주 보인다, 다른 단어도 섞어서 다양하게" 요청.

1. **히어로 옆면 스머지 장식 제거**: `paintSmear`가 캡션이 있을 때마다 옆면에 긁힌 자국 같은 장식
   텍스처를 그리고 있었음 — 사용자가 X로 표시한 "지저분한 부분" 중 하나로 판단, 호출 자체를 없애고
   옆면 캔버스는 항상 비워 둠(clearRect만).
2. **"ME" 더 크고 깔끔하게**: `CAPTION_CAP`(캡션 폰트 크기 상한)을 `0.17→0.3`으로 올려 "ME"가
   캡 앞면을 꽉 채울 만큼 커지도록 함 — 실측(스크린샷)으로 가로 폭(`room/widest` 제약)에 안 걸리고
   원하는 크기까지 커지는 것 확인.
3. **단어 분포 버그 수정("HTML이 너무 많이 보임")**: 원인은 `wordClass()`의 링 변주 공식
   `(c + 4*m) % n`이 단어가 4개(n=4)일 때 `4*m`이 항상 `n`의 배수가 되어 버려 바깥 링으로 갈수록
   달라져야 할 단어가 전혀 바뀌지 않고, 그리드 전체가 단 4개 클래스 패턴 하나로만 고정 타일링되던
   것 — 결과적으로 특정 클래스(=특정 단어)가 비대칭적으로 넓은 면적을 차지해 "유독 많이 보임" 현상이
   생김. `words`를 5개(`gcd(4,5)=1`)로 늘려(실제 스킬 목록에 있는 "Flexbox" 추가) 링마다 단어가
   실제로 순환되도록 고침 — 산수적으로 전체 그리드에 고르게 분포되는 게 보장됨.
   최종: `["HTML","CSS","Figma","Design","Flexbox"]`. `index.html`의 WebGL 폴백 텍스트도 동일 반영.

  스크린샷·확대 캡처로 "ME"가 크고 흰색으로 선명하게 보이는 것, 옆면 스머지가 사라진 것, 주변 캡에
